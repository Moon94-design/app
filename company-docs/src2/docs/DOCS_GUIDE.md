# src2/docs 사용 가이드

> 📍 **SSOT 위치: company-docs/src2/docs/** (기존 /workspaces/app/src2/docs/는 백업)
>
> ⚠️ **이 문서를 이미 읽었고 내용을 컨텍스트에 가지고 있다면 다시 읽지 마라. 중복 읽기 금지.****
>
> ⚠️ **이전 작업 내용을 모르는 상태(새 대화)라면, result/ 폴더의 가장 최근 파일을 참조하여 현재 진행 상황을 파악하라.**
>
> 이 문서는 docs 폴더 내 모든 문서의 용도, 참조 시점, 작성 규칙을 정의한다.
> Copilot은 새 대화에서 이 문서를 읽는다.
> **단, 현재 대화 컨텍스트에 이 문서 내용이 이미 존재하면 다시 읽지 않아도 된다.**
> **코드 변경 또는 문서 변경이 있었던 턴에 result 필수** — 구현, plan, 분석, 리뷰 모두 포함.
> 단순 확인/질문만 한 경우(코드·문서 변경 0)는 생략 가능.

---

## 1. 폴더 구조

```
src2/docs/
  DOCS_GUIDE.md           ← 이 문서 (최초 진입점)
  rule/                   ← 규칙/상태/검증/이력 (SSOT)
    main_rule.md          ← 헌법 (하드룰/구조/계약/금지)
    MIGRATION_STATUS.md   ← 현황판 (페이지별 이관 상태)
    GATES_CHECKLIST.md    ← 게이트 검증표 (단계별 통과 조건)
    DECISIONS_LOG.md      ← 결정 이력 (왜 이렇게 결정했나)
  roadmap/                ← 전체 로드맵
    roadmap.md            ← Phase 0~8 전체 단계 맵 + 세분화
  result/                 ← 작업 결과 기록 (단계/주제별 폴더)
    {주제폴더}/
      NNN-{제목}.md       ← 번호-제목 형식 (하이픈 고정)
```

## 2. 각 문서별 용도와 참조 시점

### rule/main_rule.md — 헌법
| 항목 | 내용 |
|------|------|
| 용도 | 하드 룰, 절대 금지, 폴더 구조, alias, 게이트, Repo/Draft 계약, 작업 템플릿 |
| **읽기 시점** | **매 대화 시작 시 필수**. 단, 현재 대화 컨텍스트에 이미 있으면 생략 가능 |
| 쓰기 시점 | 규칙 추가/변경 시 (DECISIONS_LOG에도 기록) |
| 규칙 | 이 문서의 규칙을 위반하는 코드는 작성 금지 |

### rule/MIGRATION_STATUS.md — 현황판
| 항목 | 내용 |
|------|------|
| 용도 | 단계별 진행 상태 + 전체 페이지(26개) 이관 상태 + kernel 정본화 현황 |
| 읽기 시점 | 작업 시작 전 "현재 상태" 파악 시 |
| **쓰기 시점** | **단계 완료, 페이지 이관 완료, 상태 변경 시 즉시 업데이트** |
| 상태 코드 | LEGACY → SHADOW → MIGRATED / NEW / PLANNED / BLOCKED |

### rule/GATES_CHECKLIST.md — 게이트 검증표
| 항목 | 내용 |
|------|------|
| 용도 | G0~G4 게이트 체크리스트 + 흔한 실패 원인/대응 |
| **읽기 시점** | **단계 완료 직전 — 게이트 검증 시** |
| 쓰기 시점 | 체크 완료 시 [ ] → [x] 표시. 새 게이트 추가 시 |
| 규칙 | 게이트 통과 못 하면 다음 단계 진입 금지 |

### rule/DECISIONS_LOG.md — 결정 이력
| 항목 | 내용 |
|------|------|
| 용도 | 전환 중 결정/예외/변경사항 기록. "왜 이렇게 했지?" 추적용 |
| 읽기 시점 | 기존 결정과 충돌하는 상황 / 규칙 변경 논의 시 |
| **쓰기 시점** | **새로운 결정, 예외 허용, 규칙 변경 시 즉시 추가** |
| 포맷 | `날짜 \| 결정 \| 이유 \| 대안 \| 영향 \| 되돌림 비용` |

### roadmap/roadmap.md — 전체 로드맵
| 항목 | 내용 |
|------|------|
| 용도 | Phase 0~8 전체 단계 맵. 큰 그림 + 현재 실행 단계 세분화 |
| 읽기 시점 | 전체 방향 확인 / 다음 Phase 진입 시 / 길을 잃었을 때 |
| 쓰기 시점 | Phase 세분화 추가 / 순서 변경 시 |

## 3. Copilot 작업 흐름

```
[대화 시작]
  │
  ├─ 1. 이 문서(DOCS_GUIDE.md) 읽기
  ├─ 2. main_rule.md 읽기 (컨텍스트에 이미 있으면 생략)
  ├─ 3. MIGRATION_STATUS.md로 현재 상태 확인
  │
  ├─ [작업 수행]
  │     ├─ 규칙 위반 의심 → main_rule.md 재참조
  │     ├─ 결정 필요 → DECISIONS_LOG.md 기존 결정 확인 후 추가
  │     └─ 단계 완료 → GATES_CHECKLIST.md로 검증
  │
  ├─ [작업 완료]
  │     ├─ MIGRATION_STATUS.md 상태 업데이트
  │     ├─ GATES_CHECKLIST.md 체크 표시
  │     └─ result/ 에 결과 파일 작성 (마지막)
  │
  └─ [대화 길어짐 (20턴+) / 단계 전환]
        └─ main_rule.md 다시 읽기
```

## 4. result/ 폴더 규칙

### 폴더 구조
```
result/
  {주제폴더}/          ← 단계/주제별 그룹
    NNN-{제목}.md      ← 번호-제목 (하이픈 고정)
```

### 번호 규칙
- 각 주제폴더 안에서 **생성 순서대로 3자리 번호** (001, 002, 003...)
- 예: `001-consultation-review.md`, `002-feedback-response.md`
- ⚠️ 구분자는 **하이픈(-)만 사용**. 언더스코어(_) 금지.

### 주제폴더 명명
- 단계별: `phase1-entry-shadow/`, `phase2-repo-infra/` 등
- 주제별: `src2-migration-plan/`, `kernel-design/` 등
- 관련 결과가 없는 새 주제 → 새 폴더 생성

### 작성 시점
- **코드 변경 또는 문서 변경이 있었던 턴에 result 파일 작성** (구현, plan, 분석, 리뷰 모두 포함)
- plan 모드에서 계획을 세운 경우에도 반드시 result 파일 생성
- 단순 확인/질문만 한 경우(코드·문서 변경 0)는 생략 가능

### 결과 파일 포맷
```markdown
# {제목}

> 작성일: YYYY-MM-DD
> 주제: {한 줄 요약}

---

{본문}
```

## 5. 문서 작성/수정 시 공통 규칙

| 규칙 | 설명 |
|------|------|
| 반복 생성 문서 | 파일명 앞에 **번호 필수** (NNN-title.md, 하이픈 고정) |
| 1회성 SSOT 문서 | 번호 불필요 (main_rule.md, roadmap.md 등) |
| 문서 수정 | 기존 내용 삭제 대신 업데이트. 이력은 DECISIONS_LOG에 |
| 폴더 생성 | docs/ 하위에 관련 폴더가 없으면 새 폴더 생성 가능 |
| 참조 지시 | 사용자가 "main_rule 참조" 한 마디면 충분 |
