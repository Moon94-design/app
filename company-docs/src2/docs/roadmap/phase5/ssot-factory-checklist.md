# SSOT 공통섹션 공정 체크리스트

작성일: 2026-02-10
목적: 공통 폼 섹션을 빠르게 SSOT로 고정하기 위한 반복 공정

================================================================================
0) 사전 고정
- [ ] 범위를 1개 공통섹션으로 제한(동시에 2개 이상 금지)
- [ ] 대상 도메인 2개 이상 지정(최소 Partner + Vendor)
- [ ] 완료기준(재사용/게이트/문서) 명시
- [ ] 1도메인 예외 승격 시 DECISIONS_LOG에 예외 근거/종료조건 선기록

1) 커널 생성
- [ ] `src2/kernel/components/<topic>/` 경로 생성
- [ ] 공통 컴포넌트 파일 생성(뷰 책임만)
- [ ] `index.ts` export 구성

2) 도메인 규칙 분리
- [ ] 판정/정규화/중복정책은 `src2/kernel/schema/<domain>/` helper로 이동
- [ ] 컴포넌트 내부에서 도메인 규칙을 직접 하드코딩하지 않음
- [ ] `kernel/components`에서 도메인 helper 직접 import를 피하고, 필요 규칙은 props 주입/adapter 결합으로 처리

3) 페이지 연결(최소 2도메인)
- [ ] 첫 도메인(Partner) 기존 section 대체
- [ ] 두 번째 도메인(Vendor/Agency 등) 재사용 연결
- [ ] 페이지 파일은 조립 책임만 유지

4) 금지 규칙 확인
- [ ] `@legacy` import 0
- [ ] `repo/impl` 직접 import 0
- [ ] storage key 하드코딩 0
- [ ] localStorage 직접 접근 0
- [ ] 새 key는 `keys.ts`에만 추가하고, `DECISIONS_LOG`에 `repo:*` 통일 트리거 확인

5) 게이트
- [ ] `npm run build`
- [ ] 대표 URL 직접 입력/새로고침 확인
- [ ] 기능 최소 동작 확인(추가/수정/삭제/초기화 중 해당 항목)

6) 문서 반영
- [ ] MIGRATION_STATUS에 필요한 메모 반영
- [ ] work-order 또는 SSOT 적용 기록 문서 작성
- [ ] result 파일 기록(중요 작업이면 새 번호)

================================================================================
시간 박스
- 공통 섹션 1개당 목표: 60~120분
- 30분 내 재사용 포인트가 안 잡히면 범위를 축소하고 다음 섹션으로 이동
- 파일 350 LOC 초과 시 즉시 분리
