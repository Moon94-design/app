# 유통 반품 상태/표시 규칙 로드맵 (Phase 5 배치)

작성일: 2026-02-13
범위: 유통 반품 입력/표시/집계 규칙 고정 + 반품 관련 훅 분리
상태: 실행 전(문서 확정)

================================================================================
0) 목표
- 반품 표시 규칙을 단일 기준으로 고정해 등록/관리/향후 조회에서 해석이 달라지는 문제를 막는다.
- `useRegisterLogisticsPage.ts` 비대화를 줄이기 위해 반품 전용 흐름을 별도 기능 파일로 분리한다.

================================================================================
1) 확정 규칙(SSOT)

1. 색상 규칙(2색 고정)
- 반품 기록 라인: 초록색
- 반품 대상(원본) 라인: 빨간색

2. 상태 텍스트(2개만 사용)
- `전량 반품`
- `부분 반품`

3. 중량 표기(통일)
- 반품 기록 라인: `반품중량(원중량)`
- 반품 대상(원본) 라인: `원중량(반품중량)`

4. 금액/집계 규칙
- 반품 대상(원본) 라인에서만 순금액(원금액-반품금액)을 반영한다.
- 반품 기록 라인 금액은 참고용 표시만 하고, 합계 계산에는 포함하지 않는다.
- 전량 반품 대상 라인의 금액은 `0`으로 표시한다.

5. 저장/표시 분리 규칙
- 표시 텍스트는 `반품`으로 보이되, 내부 저장 방향은 원본의 반대 방향으로 저장한다.
- 반품 판단/집계의 기준 데이터는 `isReturn`, `returnSource*`, `source*`, `returnedKg` 메타를 사용한다.

================================================================================
2) 근거리 실행 계획(상세)

배치 R1: 훅 비대화 감축 + 반품 입력 고정
- 범위:
  - `useRegisterLogisticsPage.ts`에서 반품 관련 selector/action을 별도 파일로 추가 분리
  - 반품 체크 시 차량값을 즉시 비우고 재선택 강제
  - 반품 원본 선택 이후 방향/종류/품목 수정 잠금
- 완료 기준:
  - 기존 저장/수정 플로우 회귀 0
  - 파일맵(`feature-files-map-unified.md`) 동기화

배치 R2: 등록 화면 하단 반품 상태 표기 통일
- 범위:
  - 반품 기록/반품 대상 상태를 `전량 반품`/`부분 반품` 텍스트로 통일
  - 색상은 반품 기록(초록), 반품 대상(빨강)으로만 고정
  - 중량 표기를 SSOT 형식으로 통일
- 완료 기준:
  - 등록 하단 목록에서 반품 관계를 오해 없이 식별 가능

배치 R3: 관리 펼치기 표기/금액 규칙 통일
- 범위:
  - 상태칸: 텍스트 2종(`전량 반품`, `부분 반품`) + 색상 2종(초록/빨강)
  - 중량칸: 반품 기록 `반품중량(원중량)`, 반품 대상 `원중량(반품중량)`
  - 금액칸: 반품 대상만 순금액 반영, 반품 기록은 참고용(합계 제외)
- 완료 기준:
  - 부분/전량 반품 시 합계와 라인 상세가 일관됨

배치 R4: 검증/회귀 자동화 보강
- 범위:
  - 부분 반품/전량 반품 시나리오를 회귀 스크립트 또는 QA 수동 시나리오로 고정
  - 문서(MIGRATION_STATUS/DECISIONS_LOG/result) 동기화
- 완료 기준:
  - `npm run check:qa` 기준 PASS
