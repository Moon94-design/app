# Excel 이관 전체 로드맵 (Phase 5 확장)

작성일: 2026-02-10
범위: `/excel` 허브의 단계적 이관 + 다중 포맷 통합 준비
전제: 1.5단계 브리지(`@app2/pages/excel` + legacy 내부 래핑) 적용 완료
상태: 진행 중

================================================================================
목표
- `/excel` 진입/라우팅 기준을 src2로 고정하고, 내부 기능을 단계적으로 교체한다.
- KORA 1열 + 기타 포맷 2열 구조를 지원할 수 있도록 adapter/schema SSOT를 만든다.
- 여러 엑셀 소스가 하나의 통합 엔티티(`canonicalId`)로 합쳐지는 병합 경로를 준비한다.

================================================================================
핵심 원칙
- 1차는 동작 동일성(사용자 체감 변화 최소) 우선.
- 파서/저장/병합을 한 번에 바꾸지 않고, 단계별로 분리.
- kernel은 계약/타입/정책만 먼저 고정하고, 구현은 래핑 -> 치환 순으로 진행.

================================================================================
단계 로드맵
1) 1.5단계 브리지 고정 (완료)
- `/excel` loader -> `@app2/pages/excel/ExcelImportHubPage`
- 내부는 legacy 허브를 섹션 래핑으로 유지
- 게이트: build + `/excel` URL 200

2) 2단계 adapter 계약 고정 (완료)
- `kernel/adapters/excel/common` 공통 타입/결과 포맷 고정
- `kernel/adapters/excel/kora/*` 소스별 엔트리 함수 고정
- `kernel/schema/excel/*`에 canonical/source/mergePolicy 인터페이스 고정
- 게이트: build

3) 3단계 소스별 래핑 치환 (진행 중)
- partner/weighing/vehicle 래퍼에 실제 파서 호출 연결 완료
- 레거시 파서 "이동"이 아니라 src2 래퍼에서 호출 규약 먼저 통일
- 남은 작업: `/excel` UI를 src2 섹션으로 점진 치환
- 게이트: build + 소스별 최소 샘플 업로드 1회

4) 4단계 저장 경로 정리 (다음)
- 엑셀 업로드 결과 저장을 domain repo 경유로 통일
- 키 혼재 도메인(vehicle 등)은 이관 시점에 단일 키로 정리
- 게이트: 업로드 직후 manage 반영 확인

5) 5단계 통합 병합(AB+C) 경로 구현 (Phase 5 후반~6 준비)
- `canonicalId` 기준 필드 병합 구현
- 필드 출처(origin: sourceId/sourceRowId/importedAt) 추적 추가
- 충돌 규칙은 `mergePolicy`로 분리
- 게이트: 중복/상충 케이스 회귀 검증

6) 6단계 레거시 제거 (마무리)
- `/excel`에서 legacy 컴포넌트 래핑 제거
- source adapter/parse/storage가 모두 src2+kernel 경유인지 확인
- MIGRATION_STATUS를 `MIGRATED`로 상향

================================================================================
소스 우선순위 제안
- KORA 1열: 거래처, 계량현황, 차량 (현재 운영 포맷)
- 기타 2열: 이후 신규 포맷(외부 기관/거래처별 템플릿)
- 충돌 시 기본 정책:
  - 같은 sourceId 내부: 최신 importedAt 우선
  - 다른 sourceId 간: mergePolicy 명시 전까지 덮어쓰기 금지(보류 표시)

================================================================================
게이트/검증 전략
- 기본: `npm run build`
- 보조: `npm run test:smoke` (환경 timeout 시 후속 재검증 항목으로 유지)
- 대체(현재 적용): `npm run build` + `/excel` 경로 200 + 소스별 수동 업로드 시나리오
- 수동 최소 시나리오:
  - partner 엑셀 1회 업로드 -> 저장/조회 반영 확인
  - vehicle 엑셀 1회 업로드 -> 저장/조회 반영 확인
  - weighing 엑셀 1회 업로드 -> 저장/조회 반영 확인

리스크/주의
- 엑셀 허브는 다도메인 결합 지점이라, 범위를 넓히면 회귀가 급증한다.
- vehicle처럼 레거시/신규 키가 공존하는 도메인은 이관 시점 동기화 전략이 필요하다.
- 통합 병합(AB+C)은 정책이 먼저이고, 구현이 나중이다. 정책 없이 코드부터 작성 금지.
