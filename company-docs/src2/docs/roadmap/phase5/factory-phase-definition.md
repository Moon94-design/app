# Phase 5 재정의 (Factory 공정 고정)

작성일: 2026-02-09
목적: Phase 5를 “페이지 이관 공장 공정”으로 고정하고, Phase 6 구현은 보류한다.

================================================================================
핵심 선언
- Phase 5 = 페이지 단위 반복 공정(1페이지 = 1작업 단위)
- Phase 6(서버/DB/인증)는 Phase 5 핵심 기능군 안정화 전까지 구현 시작 금지(문서 유지 가능)

================================================================================
작업 단위(고정)
- 단위: 1페이지(1라우트) 단위로 `MIGRATED` 상태를 획득
- 목표: 페이지 파일은 얇게(조립 책임만), 기능은 분리/재사용 가능 구조로 이동

================================================================================
Phase 5 완료 정의(DoD)
- 기존(레거시) 주요 페이지가 src2로 이관되어 navConfig loader가 src2를 가리킨다.
- 신규로 필요한 페이지(예: 일일기록 조회/관리 확장)가 src2에 추가되어 운영 흐름이 막히지 않는다.
- 모든 이관 페이지가 공통 페이지 DoD를 충족한다.

[공통 페이지 DoD]
- src2/app/pages/...에 존재
- navConfig loader가 src2 페이지를 가리킴(path 유지)
- 해당 페이지 @legacy import 0
- @kernel만 사용(repo는 domain repo, draft는 useDraft)
- npm run build 성공
- npm run dev에서 해당 경로 정상 렌더
- URL 직접 입력/새로고침 OK
- result 기록 완료

================================================================================
Phase 6 진입 조건(보류 해제 기준)
- 마스터/일일기록 기능군이 운영 안정화 수준으로 동작(핵심 흐름 깨짐 없음)
- kernel(schema/repo/draft) 규칙 위반 0
- Phase 5 미완료 상태에서 Phase 6 구현 시작 금지
