# Phase 5 이후 로드맵 (일일기록 우선 리뉴얼 기준)

작성일: 2026-02-13
범위: 유통 일일기록 리뉴얼 이후 ~ Phase 8 종료
기준: `src2` SSOT + `main_rule.md` + 현재 제품 방향(일일기록 우선)

================================================================================
0) 전제 변경 (고정)
- 기존 `browse` 페이지는 운영 대상이 아니라 기능 참고용이다.
- browse는 현재 리뉴얼 우선순위에서 제외하고 추후 신규 재작성한다.
- 지금 실행 순서는 아래와 같이 고정한다.
  - 1순위: 일일기록 페이지(유통 제외) 리뉴얼
  - 2순위: 기준페이지 리뉴얼
  - 3순위: 엑셀등록 리뉴얼

================================================================================
1) 현재 진행률 스냅샷
- 유통(` /register/daily/logistics `): 거의 완료(마감 단계)
- 일일기록 나머지(office/production/issue/action): 리뉴얼 배치 시작 전
- 기준페이지: src2 이관은 되었지만 운영/구조 리뉴얼 배치 필요
- 엑셀등록: 리뉴얼/종류 확장 배치 착수 전

================================================================================
2) 근거리 로드맵 (상세) — 0~6주

2-1) Wave D (0~2주): 일일기록 우선 리뉴얼

작업 D1: 유통 리뉴얼 마감
- 범위:
  - 저장/수정/초기화/이슈-조치 연계 회귀 점검
  - site fallback(구데이터) 검증 고정
  - 반품 상태/중량/금액 표기 규칙 고정(전량/부분 + 반품기록/대상 구분)
  - 문서/체크리스트 마감
- 완료 정의:
  - `npm run build` + `npm run check:qa` 통과
  - 운영 회귀 체크 시나리오 통과
  - 세부 기준은 `logistics-return-status-roadmap.md`를 SSOT로 참조

작업 D2: 유통 제외 일일기록 리뉴얼 1차
- 대상:
  - `/register/daily/office`
  - `/register/daily/production`
  - `/register/daily/issue`
  - `/register/daily/action`
- 완료 정의:
  - 각 페이지 핵심 플로우 parity
  - 공통 규칙(DailyMetaFields/site/title/tag) 위반 0

작업 D3: 일일기록 신규페이지 준비
- 범위:
  - 신규 페이지 목적/입력 필드/저장 계약(repo/draft/schema) 확정
  - 1차 구현 작업순서(페이지/훅/섹션) 확정
- 완료 정의:
  - 기능 스펙 문서 + 작업순서표 고정

2-2) Wave M (2~4주): 기준페이지 리뉴얼

작업 M1: 기준페이지 리뉴얼 배치 1
- 대상:
  - `/manage`
  - `/manage/master`
- 핵심:
  - 운영 정합성/문구/플로우 정리
  - 상태코드(SHADOW/MIGRATED) 판정 근거 명문화
- 완료 정의:
  - 운영 기준 충족 시 상태 갱신

작업 M2: 고LOC 구조 개선
- 대상:
  - `app/pages/partner/PartnerRegisterPage.tsx`
- 방향:
  - page 조립 / hook orchestration / section UI 분해
- 완료 정의:
  - 고LOC 리스크 완화 + 동작 회귀 0

2-3) Wave X (4~6주): 엑셀등록 리뉴얼

작업 X1: 엑셀등록 리뉴얼 1차
- 범위:
  - 엑셀 허브 UX/흐름 정리
  - 신규 종류 스펙(필드 매핑/정규화) 고정
- 완료 정의:
  - 종류별 매핑표 + 우선순위 목록 확정

작업 X2: 엑셀 신규 종류 구현 1차
- 범위:
  - 신규 종류 1~2개 parser/adapter/UI 연결
  - 실패 row/부분 성공 피드백 형식 통일
- 완료 정의:
  - 샘플 파일 기준 파싱/적용 성공
  - check:qa 통과

================================================================================
3) 중거리 로드맵 (중간 상세) — 6~12주
- 일일기록 신규페이지 라인업 확장 및 표준 템플릿 고정
- 기준페이지 리뉴얼 완료 + 유지보수성 개선(350LOC 경고 구간 해소)
- 엑셀 종류 커버리지 확장 + rule dictionary/normalization 통합
- 공통 기술부채 정리:
  - key 호환 정리(repo/local 혼재 키 분류)
  - 구데이터 fallback 정책 문서화

================================================================================
4) 원거리 로드맵 (큰 항목) — 3개월+
- Browse 신규 재작성 프로젝트
- Phase 6 서버 전환(REST + read-first)
- Phase 7 운영/보안/배포 체계 고정
- Phase 8 src 의존 0 및 전환 종료

================================================================================
5) 게이트 운영 (항상)
- 필수 검증:
  - `npm run build`
  - `npm run check:security`
  - `npm run check:qa`
- 각 작업 단위 종료 시:
  - MIGRATION_STATUS 갱신
  - result 기록
  - 필요 시 GATES 체크 업데이트

================================================================================
6) 다음 착수 순서 (지금 기준)
1. D1 유통 리뉴얼 마감
2. D2 유통 제외 일일기록 4페이지 리뉴얼 1차

5. X1 엑셀등록 리뉴얼 배치 1

7) 메모
- browse는 현재 "참고용 레거시 화면"으로만 유지한다.
- browse 관련 수정은 치명 버그 대응 외 신규 투자하지 않는다.
- 리소스는 일일기록 -> 기준페이지 -> 엑셀등록 순서로 집중한다.
