# 반품 상태 로드맵 + 기본 체크리스트 통합 정의

> 작성일: 2026-02-13
> 주제: 반품 표시 규칙 SSOT 문서화와 작업 기본 체크리스트 통합
> 해결 상태: Resolved

---

## 작업 배경
- 반품 상태 라벨/색상/중량 표기가 혼재되어 등록/관리에서 해석이 갈릴 위험이 있었다.
- 작업 시작 시 참조 문서가 분산돼 파일 비대화/공통화 누락이 반복되는 문제가 있었다.

## 변경 내용
- 반품 상태/표시 규칙 로드맵 신설:
  - `src2/docs/roadmap/phase5/logistics-return-status-roadmap.md`
  - 색상 2종(초록=반품기록, 빨강=반품대상), 텍스트 2종(전량 반품/부분 반품), 중량 표기 형식 고정
- 기본 통합 체크리스트 신설:
  - `src2/docs/rule/BASIC_EXECUTION_CHECKLIST.md`
  - 시작 로딩/범위 고정/하드룰/LOC 분리/검증 게이트/문서 동기화를 한 문서로 통합
  - 항목별로 참조 문서를 즉시 찾을 수 있게 경로를 함께 명시
- 기존 문서 연결 보강:
  - `src2/docs/rule/PAGE_RENEWAL_CHECKLIST.md`에 기본 체크리스트 선참조 추가
  - `src2/docs/roadmap/phase5/roadmap.md` / `src2/docs/roadmap/phase5/post-logistics-renewal-roadmap.md` / `src2/docs/roadmap/roadmap.md`에 신규 문서 링크 추가
- 상태/결정 로그 반영:
  - `src2/docs/rule/MIGRATION_STATUS.md`
  - `src2/docs/rule/DECISIONS_LOG.md`

## 검증
- 문서 변경 배치로 코드 빌드/QA 게이트는 실행하지 않음.

## 간단 소견 + 다음 진행 질문
- 이제 반품 표시 기준과 작업 시작 기준이 각각 단일 문서(로드맵/기본 체크리스트)로 고정돼, 다음 코드 배치에서 해석 차이와 탐색 시간을 줄일 수 있다.
- 다음 턴에서 바로 `useRegisterLogisticsPage.ts` 반품 전용 분리 + 반품 체크 시 차량 초기화를 배치 R1로 실행할까?

## 핵심 로직 3줄
- 1) 반품 상태 표시는 색상 2종(초록/빨강)과 텍스트 2종(전량/부분)으로만 운영한다.
- 2) 중량 표기는 반품기록 `반품중량(원중량)`, 반품대상 `원중량(반품중량)`으로 고정한다.
- 3) 작업 시작은 `BASIC_EXECUTION_CHECKLIST.md`를 기준으로 하고, 세부는 전용 체크리스트로 확장한다.

## 입문자 설명 3줄
- 1) 반품 줄은 이제 복잡한 상태명이 아니라 딱 두 단어(전량/부분)만 쓴다.
- 2) 초록은 반품한 줄, 빨강은 반품당한 원본 줄로 기억하면 된다.
- 3) 작업할 때는 기본 체크리스트 하나 먼저 보고, 필요하면 세부 체크리스트를 추가로 보면 된다.

## 주의 사항
- 반품 상태 규칙 문서만 바뀌고 UI 코드가 아직 완전히 따라오지 않은 구간이 있을 수 있다. 다음 코드 배치에서 등록/관리 양쪽 동시 반영이 필요하다.
- 기본 체크리스트를 만들었어도 기존 체크리스트를 건너뛰면 세부 도메인 누락이 다시 생길 수 있으니, "기본 -> 전용" 순서를 반드시 지켜야 한다.

## 향후 과정
- `src2/app/pages/register/hooks/useRegisterLogisticsPage.ts`에서 반품 흐름을 기능 파일로 분리해 LOC 리스크를 먼저 줄인다.
- `src2/app/pages/manage/sections/ManageLogisticsListSection.tsx`에 로드맵 기준 상태/중량/금액 표기를 코드로 고정한다.
- 반품 부분/전량 시나리오를 `check:qa` 또는 별도 회귀 스크립트에 추가해 표시 규칙 회귀를 막는다.

## 해결 상태
- `Resolved`: 반품 표시 SSOT 로드맵과 통합 기본 체크리스트 문서화 및 참조 연결 완료.
