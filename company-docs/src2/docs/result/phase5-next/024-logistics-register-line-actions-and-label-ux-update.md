# 유통 등록 하단 항목 리스트 UX 보강 (수정/삭제 + 제목 라벨 개선)

> 작성일: 2026-02-13
> 주제: 유통 등록 하단 리스트에서 항목 단위 수정/삭제 동작 추가 및 거래처-차량번호 라벨 통합
> 해결 상태: Resolved

---

## 배경
- 유통 등록 하단 리스트는 항목 제목이 거래처만 보이고 차량번호는 우측 보조 텍스트로 분리되어 있었다.
- 항목을 빠르게 정정하려면 관리 화면으로 이동해야 해서 등록 화면 내 작업 흐름이 끊겼다.
- 요구사항은 등록 화면에서 항목 단위 `수정/삭제`를 바로 처리하고, 항목 제목을 `거래처-차량번호` 형태로 보이게 하는 것이다.

## 반영 내용
- 하단 리스트 라벨 정리:
  - `src2/app/pages/register/sections/logistics/SelectedDateLogisticsList.tsx`
  - 항목 타이틀을 `거래처 - 차량번호`로 표시(차량 없으면 거래처만 표시)
  - 기존 우측 차량번호 보조 텍스트는 제거

- 하단 리스트 액션 버튼 배치:
  - `SelectedDateLogisticsList.tsx`
  - 카드 오른쪽에 `수정`/`삭제` 버튼을 세로(위아래) 배치
  - 버튼 클릭 시 상위 핸들러(`onEditLine`, `onDeleteLine`) 호출

- 등록 화면 항목 수정/삭제 동작 연결:
  - `src2/app/pages/register/RegisterLogisticsDailyPage.tsx`
  - 선택 날짜 기록 기준으로 항목 수정/삭제 핸들러 추가
  - 수정: 항목을 상단 폼으로 불러오기
  - 삭제: 확인 후 항목 삭제 실행

- 훅 레벨 로직 추가:
  - `src2/app/pages/register/hooks/useRegisterLogisticsPage.ts`
  - `editingLineTarget` 상태 추가(어느 항목을 수정 중인지 추적)
  - `startEditLine(recordId, lineIndex)` 추가: 항목 데이터를 유통 폼 draft로 역주입
  - `removeLine(recordId, lineIndex)` 추가: 항목 단위 삭제(라인 0개면 문서 제거)
  - 수정 모드에서 저장 시:
    - 먼저 저장(신규 라인 추가 경로 재사용)
    - 이후 기존 라인 정리 삭제를 자동 수행해 “수정” 의미를 보장

- 폼 버튼 라벨 개선:
  - `src2/app/pages/register/sections/logistics/LogisticsFormSection.tsx`
  - `src2/app/pages/register/sections/logistics/LogisticsFormActions.tsx`
  - 수정 모드일 때 저장 버튼 라벨을 `수정 저장`으로 표시

## 간단 의견 + 다음 진행 질문
- 이번 반영으로 등록 화면만으로 항목 정정 사이클(불러오기→수정 저장/삭제)이 닫혀서, 관리 화면 왕복이 줄어든다.
- 다음 배치에서 “수정 모드 진입 시 시각 표시(배지/현재 수정중 항목 하이라이트)”까지 넣을지 결정하면 UX 완성도가 더 올라간다. 진행할까?

## 핵심 로직 3줄
- 1) 하단 리스트 항목 제목을 `거래처-차량번호`로 통합해 사용자가 항목을 즉시 식별할 수 있게 했다.
- 2) 항목 카드 우측에 `수정/삭제` 버튼을 세로 배치해 항목 단위 액션을 바로 수행할 수 있게 했다.
- 3) 수정 저장은 “새 값 저장 후 기존 라인 정리 삭제” 순서로 처리해 기존 append 기반 저장 구조를 깨지 않고 수정 의미를 유지했다.

## 입문자 설명 3줄
- 1) 이제 아래 목록에서 항목을 고치고 싶으면 `수정`을 눌러 위 입력칸으로 바로 불러올 수 있다.
- 2) `삭제`를 누르면 그 줄만 지워지고, 마지막 줄이면 그 날짜 기록 문서도 같이 정리된다.
- 3) 제목이 `거래처-차량번호`로 바뀌어서 어떤 항목인지 더 빨리 구분할 수 있다.

## 주의 사항
- 현재 수정 저장은 “저장 성공 후 기존 라인 삭제” 방식이라, 저장은 됐지만 정리 삭제가 실패하면 중복 라인이 잠깐 남을 수 있다. 이 경우 안내 메시지를 띄우도록 처리했지만, 이후 회귀 테스트에 이 케이스를 추가해야 안정성이 더 올라간다.

## 향후 과정
- `src2/app/pages/register/hooks/useRegisterLogisticsPage.ts`의 수정/삭제 경로를 대상으로 회귀 케이스를 확장하고, 가능하면 `scripts/p0-consistency-regression.ts` 또는 별도 logistics UI 회귀 스크립트에 “수정 저장 후 단일 라인 유지” 시나리오를 추가한다.
- 유통 D1 마감 배치에서 등록-관리 간 데이터 표시 일치(제목/라인 수/합계)를 함께 점검한다.
