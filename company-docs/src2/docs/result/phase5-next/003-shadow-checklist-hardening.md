# SHADOW 제거 체크리스트 보강

> 작성일: 2026-02-11
> 주제: TASK_EXECUTION_CHECKLIST에 SHADOW 제거 순서/판정 기준/롤백 기준 보강

---

## 변경 요약
- SHADOW 제거 작업의 권장 실행 순서를 체크리스트 상단에 고정했다.
- SHADOW 전용 빠른 확인표에 실제 운영에서 필요한 판정 기준을 추가했다.

## 반영 파일
- `company-docs/src2/docs/rule/TASK_EXECUTION_CHECKLIST.md`

## 상세 반영 내용
- SHADOW 제거 권장 순서 추가
  - 1) `register/daily/*` 4개
  - 2) `browse/*` 5개
  - 3) `manage`, `manage/master`
- SHADOW 전용 확인표 보강
  - parity 확인을 추상 문구에서 `조회/저장/수정/삭제/F5` 5시나리오로 구체화
  - 데이터 호환을 문구 수준이 아닌 건수 비교(+key/스키마 메모)로 수치화
  - 롤백 기준(치명 이슈 시 loader 원복 조건/절차) 추가
  - MIGRATED 판정 근거(`@legacy import 0`, F5 OK, 콘솔 에러 0, 핵심 플로우 통과) 추가

## 게이트
- 문서 변경 작업으로 빌드 미실행

다음 질문: 이 순서대로 바로 Batch A(`register/daily/logistics`)부터 실행할까?

## 핵심 로직 3줄
- 1) SHADOW 제거를 배치 순서로 고정해 우선순위 혼선을 줄였다.
- 2) parity 검증을 시나리오 체크로 바꿔 “말로만 동일” 상태를 막았다.
- 3) MIGRATED/롤백 기준을 명문화해 실패 시 원복 판단을 빠르게 만들었다.

## 입문자 설명 3줄
- 1) 먼저 할 일 순서를 정해두면 중간에 다른 작업으로 새는 걸 막을 수 있다.
- 2) “동작 같음”은 느낌이 아니라 실제 버튼/새로고침 동작 체크로 확인해야 한다.
- 3) 문제 생겼을 때 되돌리는 기준을 미리 쓰면 사고 대응이 빨라진다.

## 주의 사항
- 체크리스트가 강화돼도 실제 작업에서 시나리오 증빙을 생략하면 다시 형식적인 문서가 될 수 있다.
- 배치 순서를 지키지 않고 병렬로 건드리면 회귀 원인 분리가 어려워질 수 있다.

## 향후 과정
- 다음 SHADOW 제거 작업부터 result에 `5시나리오 parity`와 `데이터 건수 비교`를 최소 증빙으로 고정한다.
- `MIGRATION_STATUS.md`의 SHADOW 11 큐와 이번 체크리스트 순서가 계속 일치하는지 매 배치 종료 때 확인한다.
