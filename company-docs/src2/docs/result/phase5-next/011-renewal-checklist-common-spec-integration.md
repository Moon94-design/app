# 체크리스트 최신화 (커먼스펙/기능맵/파일맵 선참조 강제)

> 작성일: 2026-02-12
> 주제: 리뉴얼 및 신규 페이지 작성 체크리스트를 커먼스펙 기반으로 재정의
> 이슈 상태: Resolved

---

## 작업 요약
- `PAGE_RENEWAL_CHECKLIST.md`를 리뉴얼/신규 작성 공용 체크리스트로 재구성했다.
- 체크리스트 시작 조건으로 아래 선참조를 강제했다.
  - `page-renewal-common-spec.md`
  - `feature-files-map-unified.md`
  - 도메인 기능맵(`register-daily-files.md`, `partner-manage-files.md` 등)
- 수정사항 발생 시 문서 최신화를 항상 수행하도록 의무 항목을 추가했다.
- 커먼스펙(`page-renewal-common-spec.md`)에도 참조 순서와 문서 최신화 의무를 명시해 양방향으로 고정했다.

## 변경 파일
- `src2/docs/reference/page-renewal-common-spec.md`
- `src2/docs/rule/PAGE_RENEWAL_CHECKLIST.md`

## 검증
- 문서 변경만 수행(코드 변경 없음)
- 빌드/린트 생략

## 다음 진행 질문
- 다음 턴부터 이 체크리스트 기준으로 `011`부터 기능 안정화 점검을 시작할까?

## 핵심 로직 3줄
- 1) 작업 시작 전에 커먼스펙/파일맵/도메인맵 선참조를 체크리스트로 강제했다.
- 2) 리뉴얼 체크리스트와 신규 페이지 작성 체크리스트를 분리해 용도를 명확히 했다.
- 3) 수정사항 발생 시 관련 문서를 항상 최신화하도록 의무 항목을 고정했다.

## 입문자 설명 3줄
- 1) 이제 작업 전에 어떤 문서를 먼저 봐야 하는지 순서가 정해졌다.
- 2) 기존 페이지 고치는 체크리스트와 새 페이지 만드는 체크리스트를 따로 쓸 수 있다.
- 3) 코드만 고치고 문서를 안 고치는 일이 생기지 않게 강제 규칙을 넣었다.

## 주의 사항
- 체크리스트를 만들었어도 실제로 선참조를 생략하면 문서와 코드가 다시 어긋날 수 있다.
- 도메인 기능맵이 없는 영역은 임시로 통합 파일맵만 참조하게 되어 기준이 약해질 수 있다.
- 결과 문서 번호 정책을 지키지 않으면 다시 누적 기록으로 회귀할 수 있다.

## 향후 과정
- 다음 작업부터 체크리스트 A(선참조) 항목을 먼저 체크한 뒤 구현을 시작한다.
- 도메인별 기능맵이 비어 있는 영역은 점진적으로 보강해 선참조 정확도를 올린다.
- 기능 안정화 턴에서 문서 최신화 항목(D)을 완료 기준으로 묶어 운영한다.

## 이슈 상태
