> 주제: 향후 모든 페이지 리뉴얼/생성에 사용할 공통 스펙 문서 최신화

## 작업 요약
- `page-renewal-common-spec.md`를 기준 문서용으로 전면 정리했다.
- 이번 버전에서 "분해 우선"이 아닌 "안정화/정합성 우선" 원칙을 명시했다.
- 빠른추가, dedup, 제목/태그/이슈-조치 연계, 데이터 접근 규칙, 게이트, 문서화 기준을 한 문서로 통합했다.
- 결과 문서 번호 정책(`009`, `010`, `011`...)과 누적 금지 규칙도 명시했다.

## 변경 파일
- `src2/docs/reference/page-renewal-common-spec.md`

## 검증
- 문서 변경만 수행(코드 변경 없음)
- 빌드/린트는 생략

## 다음 진행 질문
- 다음 턴에서 이 공통 스펙 기준으로 `010` 작업(기능 안정화 체크리스트 기반 회귀 점검)을 바로 시작할까?

## 핵심 로직 3줄
- 1) 리뉴얼 기준을 아키텍처/UX/저장/연계/검증/문서화로 분리해 고정했다.
- 2) 모든 기준정보 dedup을 `masterDedup` 공통 정책으로 통일했다.
- 3) 분해 작업은 중단하고 기능 정합성 우선으로 작업 방향을 전환했다.

## 입문자 설명 3줄
- 1) 이제 새 페이지 만들 때 무엇부터 확인할지 기준 문서가 한 곳으로 정리됐다.
- 2) 중복방지, 제목, 태그, 이슈/조치 연계를 페이지마다 다시 만들 필요가 줄었다.
- 3) 결과 문서도 한 파일에 계속 붙이지 않고 번호를 올려 분리 기록한다.

## 주의 사항
- 공통 스펙을 업데이트했어도 실제 페이지에 적용 여부를 매 턴 체크하지 않으면 문서-코드 간 괴리가 생길 수 있다.
- dedup 기준은 도메인마다 예외 키가 필요할 수 있으므로 적용 시 키 설계를 먼저 확인해야 한다.
- 안정화 우선 원칙을 지키되, 회귀 수정 중 임시 패턴이 들어가면 다음 턴에 정리 누락될 수 있다.

## 향후 과정
- 다음 리뉴얼/생성 작업 시작 전에 이 문서 + `PAGE_RENEWAL_CHECKLIST.md`를 같이 체크한다.
- 작업 중 공통 규칙 예외가 생기면 result에 예외 근거를 남기고 문서를 즉시 갱신한다.
- 기능 안정화 턴에서 저장/연계/중복 흐름을 우선 검증하고 필요 시 최소 수정만 적용한다.
