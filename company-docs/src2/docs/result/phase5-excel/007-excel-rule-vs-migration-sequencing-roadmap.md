# 엑셀 규칙 vs 이관 선후 로드맵 확정

> 작성일: 2026-02-11
> 주제: 규칙 선행/이관 선행 논쟁을 하이브리드 실행 순서로 고정

## 변경 요약
- 질문 포인트(규칙 먼저 vs 이관 먼저)에 대해 선후 전략 문서를 새로 작성했다.
- 결론은 `하이브리드`: 최소 규칙 기준선 -> 이관 완료 -> 검증 -> 규칙 고도화.

## 핵심 결정
- 완전 규칙 선행은 비권장(실동선 불일치 위험).
- 완전 이관 선행도 비권장(규칙 부채 누적).
- 현재 프로젝트는 `/excel` 이관 완료를 먼저 닫고, queue 기반 운영 안정화 후 규칙 고도화가 최적.

## 게이트
- 문서 변경만 수행(빌드 미실행)

다음 질문: 이 로드맵 기준으로 바로 `/excel` @legacy 제거 작업(B단계)부터 착수할까?

## 핵심 로직 3줄
- 1) 규칙은 최소 기준선만 먼저 고정하고, 완성은 운영 검증 뒤로 미뤘다.
- 2) 이관 완료(legacy 제거)를 중간 목표로 두어 실행 경로를 먼저 안정화했다.
- 3) 예외/중복을 queue로 노출해 규칙 고도화 입력값으로 재사용하도록 설계했다.

## 입문자 설명 3줄
- 1) 먼저 앱이 실제로 돌아가게 만들고, 그다음 규칙을 정교하게 다듬는 방식이다.
- 2) 처음부터 규칙을 완벽히 만들려 하면 실제 화면 동작과 안 맞을 수 있다.
- 3) 예외를 기록해두면 다음엔 같은 실수를 자동으로 줄일 수 있다.

## 주의 사항
- AI가 선후 전략을 단순화하면서 실제 운영 제약(검증 시간/데이터 품질)을 과소평가할 수 있다.
- 이관 완료 전에 규칙 확장부터 시작하면 다시 브랜치 충돌/재작업이 늘어날 수 있다.

## 향후 과정
- 다음 작업에서 `/excel` 내부 @legacy 의존 제거를 완료해 MIGRATED 조건을 먼저 닫는다.
- 이후 duplicate/exception queue를 붙여 규칙 고도화를 실제 운영 데이터 기반으로 진행한다.
