# Phase 5 파트너 관리 이관 계획

> 작성일: 2026-02-09
> 주제: Partner 관리 페이지(src2 이관) 실행 계획

---

## 목표
- Partner 관리 페이지를 src2로 이관해 도메인 완결.
- 보류 처리 해제 기능 추가.
- 검색, 일괄 수정 등 공통 기능은 재사용 가능한 형태로 분리.

## 범위
- 대상 페이지: /manage/master (Partner 관리 섹션)
- 변경 종류: src2 페이지 신규/교체 + 공통 컴포넌트/유틸 추출
- 레거시(src) 수정 금지(예외 시 DECISIONS_LOG 기록)

## 작업 단계
1) 템플릿 적용
- PartnerRegisterPage 스타일을 기준으로 src2 관리 페이지 껍데기 생성
- navConfig loader를 src2 관리 페이지로 교체

2) 데이터/상태 정리
- domain repo 사용 유지(@kernel/repo/domain)
- 보류 상태 로직 점검: 완료 판정에서 pending을 분리, 해제 동작 추가

3) UI 기능 추가
- 검색: 거래처명만 필터
- 보류 해제 버튼 추가
- 일괄 수정 모드:
  - 다중 체크 후 일괄 수정 폼 표시
  - 체크박스로 적용 필드 선택(중요도/관계현황/참고사항/프로필)
  - 고유 필드(이름/코드 등)는 일괄 수정에서 제외
  - 프로필 일괄 수정 방식 2종:
    - 추가: 동일 프로필은 중복 추가하지 않고 적용
    - 덮어쓰기: 기존 프로필을 모두 제거 후 새 프로필로 대체
  - 프로필 중복 판단: direction + item + kind가 모두 같으면 동일로 처리
  - 일괄 수정은 되돌리기 제공(일괄 적용 직전 상태로 1회 롤백)
  - 되돌리기는 페이지 이탈/새로고침 후에도 가능해야 함(스토리지에 스냅샷 보관)

4) 공통화
- 검색/일괄 수정/체크 리스트 등 재사용 가능 부분은 분리(components 또는 hooks)

5) 검증
- G4 기준: build/dev/URL refresh + create/edit 분기와 충돌 없음
- 보류 해제 후 완료 판정 정상 반영

## 리스크/메모
- 대량 업데이트 시 성능(상태 변경 범위 최소화)
- 완료 판정 규칙은 kernel/schema로 이동 고려

## 산출물
- src2 관리 페이지
- 재사용 가능한 검색/일괄수정 UI/로직
- result 문서 기록

되돌리기 스냅샷 보관 기간: 다음 일괄 수정 시 덮어쓰기(옵션 2)
