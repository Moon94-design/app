# 엑셀 계획 역할스위치 점검 반영

> 작성일: 2026-02-10
> 주제: 역할스위치 점검에서 나온 3개 보완사항(상태 동기화/저장경로 점검/대체 게이트) 문서 반영

---

## 변경 요약
- 엑셀 전체 로드맵의 단계 상태를 실제 코드 진행도에 맞게 동기화했다.
- 작업순서표에서 저장 경로 점검 항목을 현재 기준으로 명확화했다.
- smoke timeout을 보완하기 위한 대체 게이트를 공식 체크 항목으로 고정했다.

## 수정 문서
- `company-docs/src2/docs/roadmap/phase5/excel-migration-roadmap.md`
  - 2단계 상태: 진행 중 -> 완료
  - 3단계 상태: 다음 -> 진행 중(래퍼 연결 완료, UI 치환 잔여)
  - 대체 게이트(build + 경로 200 + 수동 업로드 시나리오) 추가
- `company-docs/src2/docs/roadmap/phase5/work-order-excel-import-hub-migration.md`
  - 저장 경로 점검 상태를 현재 수준으로 업데이트
  - 대체 게이트 체크 항목 추가

## 적용 의도
- 문서/실행 상태 불일치를 줄여 다음 단계 우선순위를 흔들리지 않게 하기 위함.

다음 질문: 지금부터는 `/excel` UI 점진 치환(legacy panel -> src2 section) 단계로 바로 넘어갈까?

## 핵심 로직 3줄
- 1) 단계 상태를 "코드 실제 상태"와 맞춰 계획 문서를 동기화했다.
- 2) 저장 경로 점검 항목에 도메인별 현재 상태(partner/weighing 확인, vehicle 후속)를 명시했다.
- 3) smoke 실패 시에도 검증 공백이 없도록 대체 게이트를 체크리스트에 고정했다.

## 입문자 설명 3줄
- 1) 계획표가 실제 진행과 다르면 다음 작업에서 헷갈리니, 상태를 먼저 맞춘다.
- 2) "완료/미완료"를 한 줄로 정확히 써두면 나중에 다시 확인할 때 시간이 줄어든다.
- 3) 자동 테스트가 느릴 때도 최소 확인 방법을 정해두면 작업 품질을 유지할 수 있다.

## 주의 사항
- 문서 상태는 맞췄지만, 실제 업로드 샘플 검증이 누락되면 다음 UI 치환 단계에서 회귀가 발생할 수 있다.

## 향후 과정
- 다음 단계에서 src2 엑셀 섹션을 붙일 때는 소스별 수동 업로드 3종(거래처/계량/차량)을 반드시 같은 기준으로 검증해야 한다.
- vehicle 키 단일화는 별도 턴으로 분리하여 manage 연계 검증과 함께 처리한다.
