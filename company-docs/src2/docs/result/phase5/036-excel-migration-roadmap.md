# 엑셀 이관 전체 로드맵 문서화

> 작성일: 2026-02-10
> 주제: `/excel` 단계적 이관과 다중 포맷 통합 준비를 위한 전체 로드맵 추가

---

## 변경 요약
- `/excel` 전용 전체 로드맵 문서를 신규 작성했다.
- 1.5 브리지 -> adapter 계약 -> 소스별 래핑 -> 저장 경로 정리 -> 통합 병합 -> 레거시 제거의 6단계로 고정했다.
- phase5 메인 로드맵에 엑셀 전체 로드맵 링크를 추가했다.

## 추가/수정 문서

  - 목표/원칙/단계별 계획
  - 소스 우선순위(KORA 1열, 기타 2열)
  - 게이트/검증 전략과 리스크
- 수정: `company-docs/src2/docs/roadmap/phase5/roadmap.md`
  - Factory 연동 문서 목록에 엑셀 전체 로드맵 링크 추가

## 적용 의도
- 지금처럼 브리지로 빠르게 이관하면서도, 이후 AB+C 병합 요구까지 설계 누락 없이 연결하려는 목적이다.

다음 질문: 다음 단계로 `3단계(소스별 래핑 치환)`에 들어가서 partner/weighing/vehicle 순으로 래퍼 호출 규약을 맞출까?

## 핵심 로직 3줄
- 1) `/excel` 이관을 단일 작업이 아니라 6단계 파이프라인으로 분해했다.
- 2) 통합 병합(AB+C)은 `mergePolicy` 정책 선행 후 구현으로 순서를 고정했다.
- 3) KORA/기타 포맷 확장과 검증 게이트를 문서 단계에서 SSOT로 고정했다.

## 입문자 설명 3줄
- 1) 큰 기능은 한 번에 바꾸지 말고 단계로 나누면 실패를 크게 줄일 수 있다.
- 2) 엑셀 데이터를 합칠 때는 먼저 "어떻게 합칠지 규칙"을 정해야 나중에 안 꼬인다.
- 3) 어떤 포맷을 먼저 할지 우선순위를 정해두면 개발 순서가 흔들리지 않는다.

## 주의 사항
- AI가 패턴에 맞춰 문서를 빠르게 만들었지만, 실제 업로드 샘플 기준 검증 시나리오가 부족하면 실행 단계에서 누락이 생길 수 있다.
- smoke timeout이 계속 남아 있어 자동화 게이트 신뢰도가 낮은 상태다.

## 향후 과정
- 다음 작업에서 소스별 래퍼를 실제 파서 호출과 연결하면 `/excel` 업로드 흐름 전체에 영향이 생기므로 도메인별 샘플 파일 검증을 먼저 고정해야 한다.
- vehicle 키 단일화 시점에는 manage 연계 데이터 반영 검증(업로드 직후 조회/편집)을 같이 체크해야 한다.
