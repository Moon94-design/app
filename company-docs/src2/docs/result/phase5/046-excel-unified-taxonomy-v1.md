## 변경 요약
- 네가 답한 운영 원칙을 기준으로 통합 분류 SSOT v1 문서를 신규 작성했다.
- 핵심은 `같은 PP/PE라도 매입/매출 맥락으로 분리`와 `예외 분류 학습 루프`를 고정한 것이다.

## 추가 문서
- `company-docs/src2/docs/reference/excel-unified-taxonomy-v1.md` (신규)
  - 실사용 대분류 4개: `원재료매입/서비스/운송료/가공품매출`
  - 원재료 트리: `스크랩(비압축)`/`압축품` + PP/PE + 기준 태그 + 사용자 태그
  - site 정책: 분류키가 아니라 태그로만 처리
  - 예외 큐 UI 흐름: 카테고리 버튼 -> 항목 선택 -> 일괄 분류
  - 학습 규칙 승격: 동일 확정 2회 이상 시 자동 후보
  - 기본 규칙 vs 학습 규칙 분리 저장 원칙

- 문서 작업만 수행(빌드 미실행)

다음 질문: 이 SSOT v1 기준으로 `rule dictionary` 초안(JSON/문서)까지 바로 만들까?

## 핵심 로직 3줄
- 1) `PP/PE`는 단어가 같아도 매입(원재료)과 매출(가공품)로 반드시 분리한다.
- 2) 원재료는 `스크랩(비압축)`과 `압축품`을 루트로 두고 PP/PE 하위 태그로 세분화한다.
- 3) 자동 분류 실패 항목은 예외 큐에서 수동 분류하고, 반복 확정된 규칙만 학습 규칙으로 승격한다.

## 입문자 설명 3줄
- 1) 같은 단어라도 상황(매입/매출)이 다르면 다른 종류로 다뤄야 데이터가 맞다.
- 2) 큰 분류부터 정하고(원재료/운송/서비스/매출), 그 아래에 태그를 붙이면 관리가 쉬워진다.
- 3) 자동 분류가 틀릴 수 있으니, 사람이 고친 결과를 점진적으로 학습시키는 구조가 안전하다.

## 주의 사항
- AI가 규칙 문서를 빠르게 만들면서 실제 입력 UI에서 선택/확정 단계 누락을 놓칠 수 있다.
- 학습 규칙 승격 기준이 너무 느슨하면 오분류가 자동화로 전파될 위험이 있다.

## 향후 과정
- 다음 단계에서 rule dictionary를 만들 때 `base/learned`를 분리 저장해야 추후 교정이 가능하다.
- 이 분류 체계가 적용되면 조회/집계 화면의 분류 필터도 같은 라벨로 동기화해야 한다.
