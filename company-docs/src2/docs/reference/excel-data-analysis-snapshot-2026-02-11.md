## 1) KORA 거래처 (대구+성주)
- 총 행수: `338`
- 거래처코드 유니크: `232`
- 중복 코드: `106`
- 교차 사이트 중복(대구/성주): `106`

해석:
- 대구/성주에 동일 거래처 코드가 공통 존재
- 중복 병합은 자동보다 `duplicateQueue` 기반 수동 확인이 안전

## 2) KORA 계량현황
- 총 행수: `1,774`
- 총중량 누락: `15`
- 공차중량 누락: `15`
- (총/공차 중 하나라도 누락) 예외 건수: `15`
- slip 번호(CW/CP) 누락: `15`
- 금액 불일치(실중량*단가 vs 금액): `2`

날짜 형식:
- `M/D/YY` 형식이 대부분 (예: `2/11/25`)
- 공란: `15`

해석:
- 누락 15건은 예외 큐에서 수동 입력/삭제 처리 필요
- 수동 보정 후에도 매칭 규칙 적용 대상에 포함 필요

## 3) KORA 차량관리
- 총 행수: `73`
- 차량규격 분포:
  - `0.5`: 52
  - `5`: 7
  - `25`: 6
  - `1`: 4
  - `2.5`: 3
  - `7.5`: 1
- 차량종류 분포:
  - `06:기타`: 52
  - `05:카고`: 20
  - `04:집게차`: 1

해석:
- 규격 정규화(`0.5/1 -> 1t`, `5 -> 5t`, `25 -> 25t`) 필요
- 종류는 `윙/카고/방통` 중심으로 매핑하고 나머지는 예외 처리 필요

## 4) Hometax 매입(세금계산서/품목)
- 세금계산서 행수: `106`
- 품목 행수: `121`
- 날짜는 전 컬럼 `YYYY-MM-DD`로 일관
- 텍스트 입력:
  - 비고/품목비고는 일부만 채워짐(미기입 다수)
  - 품목명은 상대적으로 채워짐

해석:
- 분류는 `비고 단독`보다 `품목명 + 비고` 결합 기반이 유리
- Hometax는 구조가 정형이라 전 필드 보존 전략이 유효
