# online-minimum-line-checklist
작성일: 2026-02-18
목적: 온라인 4~5인 동시사용 전환 전에 최소선(식별자/충돌/권한 경계)을 먼저 고정해 대규모 재작업을 방지한다.

---

## A) 문서 키/식별자 기준
- [ ] 일일 문서 식별 기준을 `writerName`이 아니라 `actorId(writerId)` 우선으로 고정했다.
- [ ] 기존 문서 키와의 호환 전략(fallback/read-only migration)을 명시했다.
- [ ] 기존 `writerName` 키 문서는 중복 생성 없이 `actorId` 키로 이관되도록(또는 단일키로 유지되도록) 처리 규칙을 고정했다.
- [ ] 도메인별 "1일 1문서 정책"의 키 축(`recordDate + site + actorId`)을 문서화했다.
- [ ] 동명이인/이름변경 시나리오를 키 충돌 없이 처리하는 규칙을 문서화했다.

## B) 동시편집/충돌 최소선
- [ ] 저장 전 `getById -> updatedAt(version) 비교` 충돌 가드를 도입했다.
- [ ] 충돌 발생 시 사용자 메시지 정책(재조회/재시도/병합 안내)을 고정했다.
- [ ] 충돌 시 자동 덮어쓰기를 기본값으로 두지 않는 정책을 명시했다.
- [ ] 커맨드 경계에서만 충돌 처리하고 페이지 컴포넌트는 알림/재시도 트리거만 담당하게 분리했다.
- [ ] 레코드 병합 키가 `recordDate` 단일축이 아닌 `recordDate + site + actor` 축으로 동작하는지 확인했다.

## C) 권한 분기 포인트(초기)
- [ ] `canRead/canWrite/canDelete` 인터페이스를 라우트/커맨드 경계에 추가했다.
- [ ] 초기 단계는 임시 allow 정책이더라도 분기 포인트 함수 자체는 고정했다.
- [ ] 관리/등록/조회 라우트별 권한 적용 대상 표를 문서화했다.
- [ ] 권한 실패 시 UX(차단 메시지, 대체 경로)를 문서화했다.

## D) 보안/저장 최소화
- [ ] actor 식별용 저장 데이터는 최소 필드 원칙으로 정리했다.
- [ ] 로컬 저장값 중 온라인 전환 시 서버 이관 대상/비대상 구분표를 만들었다.
- [ ] 감사로그는 목적에 필요한 최소 스냅샷만 저장하도록 기준을 문서화했다.
- [ ] 민감 데이터 반출 경로(임시 파일/콘솔/다운로드) 금지 점검 항목을 결과 문서에 남겼다.

## E) 범위 통제(대작업 방지)
- [ ] 이번 배치 적용 대상을 `일일 저장 커맨드 + 공통 경계`로 제한했다.
- [ ] 조회/관리 화면은 읽기 호환 수준만 맞추고 본 리뉴얼은 별도 배치로 분리했다.
- [ ] 변경 파일이 넓어질 경우, 경계 유틸 도입 후 페이지별 적용을 후행하도록 쪼갰다.
- [ ] "전페이지 일괄 수정"을 금지하고 순차 적용 순서를 문서에 명시했다.

## F) 검증/문서 동기화
- [ ] L0: `npm run build`
- [ ] L1/L2 조건 충족 시 `npm run check:security`, `npm run check:qa:reuse-build`
- [ ] 롤아웃 검증: 기존 키 문서가 있는 상태에서 저장 시 문서 중복(구키+신키) 없이 1건으로 유지되는지 확인했다.
- [ ] `DECISIONS_LOG.md`에 식별자/충돌/권한 기준 결정을 기록했다.
- [ ] `MIGRATION_STATUS.md`에 이번 배치 목적/범위/다음 단계를 반영했다.
- [ ] BASIC 결과 + 본 체크리스트 결과를 모두 `checklist-result`에 작성했다.
