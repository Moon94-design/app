# daily-renewal-commonization-checklist
작성일: 2026-02-13
목적: 유통 리뉴얼에서 검증한 패턴을 모든 일일 페이지(생산/사무/이슈/조치/유통)에 공용 적용해, 초안 품질을 높이고 재수정 비용을 줄인다.

---

## A) 공통 메타/작성자 정책
- [ ] 기록일/지부/작성자/직책은 공통 메타 구조를 유지한다.
- [ ] 작성자 메타는 내 정보 기반 잠금 정책을 기본값으로 적용한다.
- [ ] 지부는 내 정보 값을 초기값으로만 반영하고, 사용자 수동 변경은 항상 허용한다.
- [ ] 연동 입력(예: 일일 -> 이슈/조치)은 일지 메타(기록일/지부/작성자/직책)를 강제 고정한다.

## B) 선택/입력 UX 정책
- [ ] 선택 입력은 단일 자동완성 필드(입력 + 하단 목록) 패턴을 우선 적용한다.
- [ ] 검색은 포함 매칭(contains) 기준으로 처리한다(prefix 강제 금지).
- [ ] 입력값이 비어있을 때 목록 열기 버튼으로 전체 옵션을 노출한다.
- [ ] 입력 텍스트 자체는 저장하지 않고, 목록 선택 시에만 id/value를 확정한다.
- [ ] 도메인 기준이 고정된 선택값(예: 생산 종류/품목)은 페이지 전용 하드코딩 대신 공용 스키마 상수로 관리한다.
- [ ] quick-add 직후 선택 인식 실패 방지(fallback label/value 해석)를 적용한다.
- [ ] 선택 id -> 표시값 해석은 공용 resolver를 사용한다.
- [ ] 기본 선택지와 `기타`를 함께 쓰는 경우, `기타`는 단일 모드로 선택하고 기본 선택지와 동시 선택되지 않게 고정한다.
- [ ] `기타` 직접입력으로 등록한 값은 기본 선택지 목록에 합치지 않고, `기타` 전용 드롭다운(타이핑 포함검색)에서만 선택한다.
- [ ] 사용자 노출 문구(안내/오류/토스트/placeholder/confirm)는 반말을 사용하지 않고 존댓말로 고정한다.

## C) 초안/저장 정합성 정책
- [ ] reset 동작은 현재 페이지 기본 초안으로 일관되게 복귀한다.
- [ ] 일일 기록(유통/생산/사무/회계)은 제목 입력 UI를 노출하지 않고 템플릿 자동생성 저장을 기본으로 한다.
- [ ] 저장 시 key/ID 정책(결정론/랜덤)을 도메인 규칙에 맞게 명시한다.
- [ ] legacy 호환 로직이 있으면 1회 이관/동기화 기준을 명확히 고정한다.
- [ ] 파생 계산(중량/단가/금액/상태)은 공용 함수 우선으로 처리한다.

## D) 리스트/편집 UX 정책
- [ ] 목록 제목 규칙(핵심 식별자 조합)을 명시하고 화면별로 통일한다.
- [ ] 항목 단위 수정/삭제 액션 위치를 일관된 위치로 고정한다.
- [ ] 상태 표시는 배지 컴포넌트 우선(행 전체 배경 강조 남용 금지).
- [ ] 이슈 상태가 `완료`일 때는 같은 모달/흐름에서 조치 입력으로 이어지도록 공통 연계한다.

## E) 공용화/비대화 방지
- [ ] 페이지 파일은 조립 책임, 훅은 orchestration 책임을 유지한다.
- [ ] 큰 변경은 훅 본문 누적 대신 기능 파일(command/selector/helper)로 분리한다.
- [ ] 공용 가능 로직은 `@kernel` 또는 `hooks/common`으로 승격한다.
- [ ] 기능 분리/신설 시 `feature-files-map-unified.md`를 즉시 최신화한다.

## F) 미래 대비(조회/서버/보안/권한)
- [ ] 조회 대비: key/value/id/recordDate/site/actor 축으로 재구성이 가능하도록 필드를 유지한다.
- [ ] 조회 대비: 통계용 파생값은 원본값 + 계산규칙으로 재현 가능하게 구조화한다.
- [ ] 서버이관 대비: 페이지는 domain repo 계약만 의존하고, local/server 구현 세부와 분리한다.
- [ ] 서버이관 대비: 에러/재시도/동기화 처리는 command/repo 경계에서 다룬다.
- [ ] 보안 대비: 회사 데이터 전량 민감 취급 원칙으로 최소 노출/최소 반출을 유지하고 security-check 위반 패턴 0을 유지한다.
- [ ] 계정/권한 대비: actor 추적 필드와 권한 분기(read/write/delete) 포인트를 문서화한다.

## G) 검증/문서 동기화
- [ ] 배치 종료 시 최소 `npm run build` 통과
- [ ] 조건 충족 시 `check:security` 또는 `check:qa` 수행
- [ ] 같은 배치에서 `build`를 이미 수행한 경우 QA는 `check:qa:reuse-build` 또는 `test:smoke:routes`로 필요한 범위만 실행한다.
- [ ] `MIGRATION_STATUS.md` + result 문서를 동기화
- [ ] 결정/예외가 생기면 `DECISIONS_LOG.md`에 기록

## H) 공용 승격 고정 규칙
- [ ] 이번 작업 수정사항 중 공용화 가능한 항목은 이 원본 체크리스트에 즉시 반영한다.
- [ ] 반영 사실과 참조 경로를 채팅/결과 문서에 함께 명시한다.
