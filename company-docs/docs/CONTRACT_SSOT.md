# CONTRACT_SSOT.md (완성본 참고 자료 / 작업형 AI용 단일 기준문서)
> 목적: 매 작업마다 Copilot/Codex(작업형 AI)가 “짧게 읽고도 실수 없이” 움직이게 만드는 **단일 규약(SSOT 계약서)**  
> 원칙: **길어지면 안 읽는다.** 설명 최소, **주의/금지/성공조건** 중심.

---

## TL;DR (반드시 읽기, 7줄)
1) 이 앱은 **회사 운영 데이터 플랫폼**이다: 기준정보(마스터) + 일일기록 + 이슈/조치 + 관리 + 조회/보고서 + 권한(제공통제).  
2) 기본 모드 = **기능 변경 0**. 리팩터/분리는 “코드 이동”이 원칙.  
3) **SSOT 우선**: 재사용 블록/규칙은 `src/ssot`/`src/domain`에, 페이지는 조립 중심.  
4) **연계는 refs로 수렴**: 새로 `*_Id + *_Label` 같은 평행필드 추가 금지(기존은 마이그레이션 후보).  
5) 태그는 **UI 입력**(tagsText)과 **저장 정본**(tags[]) 분리 가능. 변환은 중앙 normalize에서.  
6) 권한은 “프론트 숨김” 금지. **서버/서비스 레이어가 제공 데이터로 통제**(특히 Browse/Report).  
7) 단계 작업 + 빌드 게이트: **작은 단계 → `npm run build` 통과 → 다음 단계**.

---

## 0) 시스템 목표/구조 (변하지 않는 큰 뼈대)
- 최종 목표: 회사에 흩어진 정보를 한 시스템에 모아
  - 기록(누가/언제/무엇을) / 연결(refs) / 파악(조회·검색·보고서) / 통제(권한 제공 차등)
- 흐름(강제 개념):
  1) **기준정보(마스터)**: 거래처/차량/설비/직원/업체/기관/품목/단가 등 “연계용 원천 데이터”
  2) **일일기록(사실)**: 하루에 벌어진 일을 구조화(마스터를 Ref로 연결)
  3) **이슈/조치(문제 해결)**: 이슈 단일 모델 + 조치 이력(refs/tags로 연결)
  4) **관리(Manage)**: 목록/필터/빠른 수정(폼 재사용)
  5) **조회/보고서(Browse/Report)**: 검색/필터/템플릿/추세
  6) **권한/보안**: 제공 통제(가리기 X)

---

## 1) 권한 정책 (현재 합의 / 짧게)
- Register/Manage(수정/연계)는 운영상 **넓게 오픈**이 필요할 수 있다.  
- 차등 통제는 **Browse/Report에서 강하게**:
  - 일반계정: **간략 조회**(요약 템플릿 중심, 고급 필터/내보내기 제한)
  - 관리자: **전체 조회/보고서 + 감사로그(계정 로그)**
- Export/대량 조회/고급 보고서는 관리자 전용.
- 구현 원칙: **프론트에서 숨기지 말고**, 서버/서비스 레이어가 **권한에 따라 내려주는 데이터 자체**를 다르게 한다.

## 2) “기능 변경 0” 기본 규칙 (리팩터 안전장치)
### 기본값
- 사용자가 “기능 바꿔”라고 명시하지 않으면: **동작 동일 유지가 최우선**.
- 리팩터는 “정리”가 아니라 “이동/분리”에 가깝게.

### 금지
- 화면/데이터/저장 포맷/동작 방식 변경
- 대규모 삭제/폴더 정리(빈 폴더 포함)  
- 무의미한 리네이밍/스타일 통일 작업(Phase 범위 밖)

### 허용(기능 변경 0 범위에서만)
- 컴포넌트/파일 분리
- import 정리(진짜 미사용만)
- 타입 에러/빌드 에러 해결(동작 유지)

---

## 3) SSOT(정본) 규칙
### 목표
- 페이지는 “조립(Compose)” 중심으로 단순화.
- 공통 입력/표현/규칙은 SSOT 블록으로 흡수.

### 실사용 핵 폴더(중요)
- `src/ssot/forms/blocks/` : TagBlock / RecordHeaderBlock / AutoTitleBlock / MainContentBlock
- `src/domain/schema/daily/` : production/issue/action/_common (정본 스키마)
- `src/data/` : repo/localRepo/issueRepo/actionRepo/keys
- `src/base/components/TagInputText.tsx` 및 관련 hooks

### 금지
- 페이지 내부에서 중복 로직을 새로 만들기(SSOT/Domain에 있어야 할 규칙을 페이지에 박기)

---

## 4) 연계(Refs) 규칙
- 장기 목표: 저장 정본은 **`refs: Ref[]`**로 수렴.
- 새 작업에서 **`*_Id + *_Label` 평행 필드 신규 추가 금지**.
- 기존 평행 필드가 남아있다면:
  - **확장하지 말고** “마이그레이션 후보”로 유지.
  - UI 편의/검색 캐시는 **인덱스/뷰 레이어**로.

---

## 5) 태그(Tags) 규칙
- UI 입력 편의: `tagsText` 가능.
- 저장 정본: `tags: string[]`(또는 ids) 권장.
- 변환/정규화는 한 곳에서만(중앙 normalize).
- 페이지마다 서로 다른 파싱 로직 금지.

---

## 6) “파일 정리/삭제” 규칙 (중요)
- 빈 폴더/미완성 페이지는 “미사용”이 아니라 “미래 슬롯”일 수 있다.
- **삭제/정리 작업은 명시 승인 없이는 금지**.
- docs/result, tools/.backups, patch 메모들은 런타임이 아니라 **작업 운영 자산**이므로 함부로 건드리지 않는다.
- 개인 메모(txt)는 사용자 편의 파일일 수 있으므로 삭제 금지.
