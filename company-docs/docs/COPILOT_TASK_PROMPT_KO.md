# Copilot 단일 작업 기준서 (Single Source of Task Truth)

> 목적: Copilot이 **여러 문서를 왔다 갔다 보지 않고**, 이 문서 하나만 읽고 안전하게 작업하도록 하는 단일 기준서.

## 최상단 요약 (5줄)
1. 기본 원칙은 **기능 변경 0** (리팩터링은 동작/UI 동일).
2. 페이지는 조립 중심, 로직은 SSOT/도메인 레이어 우선.
3. 링크는 `refs: Ref[]` 수렴, 새 평행 필드(id+label 분산) 추가 금지.
4. 작업은 작은 단계로 진행하고 단계 끝마다 `npm run build` 게이트.
5. 권한은 프론트 숨김이 아니라 **서버/서비스 데이터 제공 통제**로 처리.

---

## 1) 이 문서의 사용 규칙
- Copilot은 작업 시작 시 **이 문서만 필수로 읽는다**.
- 다른 문서는 **명시적으로 지시된 경우에만** 추가로 읽는다.
- 문서 충돌/모호함이 있으면 임의 판단하지 말고 결과 보고서 `Risks`에 기록한다.

---

## 2) 프로젝트 목표/방향 (통합 요약)
- 이 시스템은 회사 운영 데이터 플랫폼이다:
  - 기록(누가/언제/무엇)
  - 연결(관련 정보 refs)
  - 파악(검색/요약/보고)
  - 통제(권한별 데이터 제공)
- 뼈대 흐름:
  - 기준정보(마스터) → 일일기록(사실) → 이슈/조치(문제해결) → 관리(목록/수정) → 조회/보고서(인사이트) → 권한통제

---

## 3) 절대 규칙 (Hard Rules)
1. **Functional change = 0** (기본값)
2. 옮겨담기/분리 우선 (리네이밍/구조재설계/정리 금지)
3. 앵커(ANCHOR) 유지 (삭제/이름변경 금지)
4. 상태 소유권 변경 금지
5. 범위 밖 파일 수정 금지
6. “비어 보이는 파일/폴더” 삭제 금지
7. Access control은 서버/서비스 레이어에서만 강제 (프론트 role-hide 변경 금지)

---

## 4) 데이터/모델 규칙 (실무 요약)
- 링크 정본: `refs: Ref[]`
- 새 평행 저장(`equipmentId + equipmentLabel`류) 추가 금지
- 태그는 UI 입력(`tagsText`)과 저장 정규형(`tags[]`) 역할 분리 원칙 유지
- 페이지 내부 임시 파싱 로직 확산 금지 (정규화는 중앙 레이어 지향)

---

## 5) 단계별 실행 절차 (Copilot 작업 절차)
1. 스코프 3줄 요약 작성
   - 목표 / 수정 파일 / 변경하지 않을 것
2. 가장 작은 단위 1단계만 구현
3. `npm run build` 실행
4. 결과 보고서 작성 (`docs/result/YYYYMMDD_<task-name>.md`)
5. 다음 단계는 지시가 있을 때만 진행

---

## 6) 결과 보고서 필수 형식
반드시 아래 섹션 포함:
- Summary
- Files changed
- Build / checks
- Risks
- Counterexamples / 반례 및 우려사항
- References read

`References read`에는 기본적으로 아래 1개만 기록:
- `docs/COPILOT_TASK_PROMPT_KO.md`

(추가 문서를 읽은 경우에만 그 경로를 추가)

---

## 7) 복붙용 공통 지시문
```md
[공통지시]
- 이 작업은 기능 변경 0이다. 동작/UI를 바꾸지 말 것.
- 이 문서(`docs/COPILOT_TASK_PROMPT_KO.md`)를 단일 기준서로 사용.
- 옮겨담기/분리만 수행하고 리네이밍/정리/재설계 금지.
- 앵커는 유지하고, 상태 소유권 변경 금지.
- 범위 밖 파일 수정 금지, 비어 보이는 파일/폴더 삭제 금지.
- 작업 완료 후 `npm run build` 실행.
- 결과를 `docs/result/YYYYMMDD_<task-name>.md`로 작성.
- 결과 파일에 `Counterexamples / 반례 및 우려사항`을 반드시 포함.
```

---

## 8) 컨트롤타워 검수 체크포인트
- 기능/UI 동일성 유지 여부
- 앵커 보존 여부
- props 누락/오연결 여부
- build 통과 여부
- 반례/우려사항의 구체성
